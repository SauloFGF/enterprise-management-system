# DEC-012 — Refresh token lifecycle

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

Use one opaque random refresh token per User session. Persist only a SHA-256 hash in `User.RefreshToken`; store the expiry in `User.RefreshTokenExpiresAt`. Absolute lifetime is seven days. Rotate the token on every successful refresh and revoke the previous token. Logout revokes the current session. Password change, role change or soft deletion revokes the token. There is one active session per user in the MVP; multiple-device sessions are not supported.

## Rationale

Hash-at-rest and rotation reduce token exposure, while one-session semantics keep the specified User fields simple.

## Impact

Applies to TASK-006, TASK-019 through TASK-021, TASK-023 and auth tests.

## Evidence

The specification requires seven-day, persisted and revocable refresh tokens but does not define rotation or storage format.
