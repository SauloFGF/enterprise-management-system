# DEC-006 — Client document rules

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

`Client.Type` is `PF` or `PJ`. Store `Document` as digits only after removing punctuation and spaces. Validate CPF with its check-digit algorithm when the type is PF and CNPJ with its check-digit algorithm when the type is PJ. `Name` is required for both types. Email and Phone are optional for Client. Document is unique across all Client rows, including soft-deleted rows; format it only in API responses.

## Rationale

This gives the portfolio concrete PF/PJ behavior while preserving historical identity and avoiding ambiguous duplicate documents.

## Impact

Applies to TASK-007, TASK-009, TASK-031 through TASK-035 and Client tests.

## Evidence

The specification confirms PF/PJ and the Document field but leaves validation, normalization and uniqueness pending.
