# DEC-005 — Referential delete behavior

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

Use database `RESTRICT` for physical foreign-key deletes. Public delete operations only set the root `IsDeleted` flag. A soft-deleted Client or Product remains referenced by historical Orders/OrderItems; queries may return a deleted reference label but never physically remove the row. A soft-deleted Order hides its items from normal queries while preserving them.

## Rationale

Restrict prevents accidental loss of order history. Soft deletion keeps the UI and database consistent without cascading destructive changes.

## Impact

Applies to TASK-010, TASK-011, TASK-032, TASK-037 and Order tests.

## Evidence

The specification requires soft delete and defines Client → Order → OrderItem → Product relationships, but does not define cascade behavior.
