# DEC-007 — Valores monetários e arredondamento

**Status:** APROVADO  
**Data:** 24/09/2026  
**Responsável:** Tech Lead

## Decisão

Utilizar PostgreSQL `numeric(18,2)` para `Price`, `UnitPrice`, `TotalPrice` e `TotalAmount`. Tratar a moeda como BRL para o portfolio; nenhum campo Currency separado é adicionado às entidades especificadas. Calcular o total de cada linha como `round(Quantity * UnitPrice, 2)` e `TotalAmount` como a soma dos totais de linha persistidos. Todos os cálculos ocorrem no servidor.

## Justificativa

Numeric de escala fixa evita erros de ponto flutuante e fornece totais determinísticos. BRL se encaixa no contexto de negócio em português e mantém o MVP dentro dos campos especificados.

## Impacto

Aplica-se à TASK-008, TASK-009, TASK-036, TASK-037, TASK-041, TASK-043 e testes de Order.

## Evidência

A especificação define campos monetários, mas não moeda, precisão ou arredondamento.
