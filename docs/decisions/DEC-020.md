# DEC-020 — Test database

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

Use an isolated PostgreSQL Testcontainers database for integration and E2E tests. Do not use EF InMemory or SQLite for tests that verify PostgreSQL behavior. Each test run uses an isolated database/schema lifecycle and cleans only its own container. No numeric coverage threshold is required for the MVP; the suite must report executed tests and failures.

## Rationale

PostgreSQL-specific behavior, migrations, numeric precision and delete behavior should be tested against the real provider. InMemory would hide those failures.

## Impact

Applies to TASK-014, TASK-015, TASK-052, TASK-053, TASK-054 and CI. Docker becomes a development/test prerequisite for integration tests, not an application runtime requirement.

## Evidence

The specification requires PostgreSQL and integration/E2E tests but leaves test infrastructure pending.
