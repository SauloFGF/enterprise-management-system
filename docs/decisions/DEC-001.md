# DEC-001 — Contrato de erro da API

**Status:** APROVADO  
**Data:** 24/09/2026  
**Responsável:** Tech Lead

## Decisão

Utilizar RFC 7807 `application/problem+json` para erros da API. As respostas contêm `type`, `title`, `status`, `detail`, `instance`, `correlationId` e, para erros de validação, uma coleção `errors` indexada por campo.

Utilizar `400` para entrada malformada/inválida, `401` para autenticação ausente ou inválida, `403` para role insuficiente, `404` para recurso não encontrado, `409` para conflitos de duplicidade ou estado inválido, `429` para rate limiting e `500` para erro inesperado do servidor. Não retornar stack traces em produção.

## Justificativa

ProblemDetails é padrão, interoperável e evita a criação de um formato de erro customizado. O mapeamento de status fornece comportamento estável para o frontend e testes E2E.

## Impacto

Aplica-se à TASK-004, a todas as tasks de endpoints e ao tratamento de erros do frontend (TASK-013).

## Evidência

A especificação requer APIs documentadas, validação e segurança; este registro fornece o contrato faltante sem alterar o comportamento do produto.
