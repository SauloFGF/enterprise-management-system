# DEC-003 — DTO e regras de validação

**Status:** APROVADO  
**Data:** 24/09/2026  
**Responsável:** Tech Lead

## Decisão

DTOs da API são separados das entidades EF. Campos obrigatórios e limites:

- `Name`: obrigatório para User, Client e Product; 1–120 caracteres.
- `Email`: obrigatório para User; opcional para Client quando presente; Product não possui campo Email; e-mail válido, máximo 254 caracteres.
- `Phone`: opcional, máximo 30 caracteres.
- `Description`: campo opcional de Product, máximo 1.000 caracteres.
- `Role`: valor obrigatório de User, `ADMIN` ou `OPERATOR`.
- `Password`: somente escrita para criação/atualização de User; nunca retornado.
- `Price`: valor positivo com precisão de banco definida pela DEC-007.
- `Quantity`: inteiro positivo com limites definidos pela DEC-009.
- Datas, quando presentes, utilizam ISO 8601 UTC.

Respostas nunca devem expor `PasswordHash`, refresh tokens brutos ou objetos de navegação internos do EF.

## Justificativa

Separar DTOs previne over-posting e mantém a API estável quando a persistência muda.

## Impacto

Aplica-se à TASK-004, TASK-006 a TASK-009, TASK-016, TASK-018, TASK-024, TASK-026, TASK-031, TASK-036 e TASK-041.

## Evidência

A especificação define campos de domínio, mas deixa os formatos dos DTOs e limites de validação não especificados.
