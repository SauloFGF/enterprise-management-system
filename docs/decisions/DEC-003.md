# DEC-003 — DTO and validation rules

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

API DTOs are separate from EF entities. Required fields and limits are:

- `Name`: required for User, Client and Product; 1–120 characters.
- `Email`: required for User; optional for Client when present; Product has no Email field; valid email, maximum 254 characters.
- `Phone`: optional, maximum 30 characters.
- `Description`: optional Product field, maximum 1,000 characters.
- `Role`: required User value, `ADMIN` or `OPERATOR`.
- `Password`: write-only for User create/update; never returned.
- `Price`: positive value with database precision defined by DEC-007.
- `Quantity`: positive integer with limits defined by DEC-009.
- Dates, when present, use ISO 8601 UTC.

Responses must never expose `PasswordHash`, raw refresh tokens or internal EF navigation objects.

## Rationale

Separating DTOs prevents over-posting and keeps the API stable when persistence changes.

## Impact

Applies to TASK-004, TASK-006 through TASK-009, TASK-016, TASK-018, TASK-024, TASK-026, TASK-031, TASK-036 and TASK-041.

## Evidence

The specification defines domain fields but leaves DTO shapes and validation limits unspecified.
