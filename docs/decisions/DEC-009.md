# DEC-009 — Order items and transaction

**Status:** APPROVED  
**Date:** 24/09/2026  
**Owner:** Tech Lead

## Decision

`Quantity` is an integer from 1 to 9,999. A single Order cannot contain the same Product more than once. `UnitPrice` is copied from Product.Price when the item is created and is not changed by later Product edits. Creation and item edits run in one database transaction. A pending Order may be edited; completed/cancelled Orders cannot. Recalculate totals after every accepted item change and roll back the entire transaction on any validation or persistence error. Use row locking for the Order during write operations; no stock is checked because stock is out of scope.

## Rationale

The rules preserve historical prices, avoid ambiguous duplicate lines and prevent partial orders.

## Impact

Applies to TASK-009, TASK-041 through TASK-047 and Order test fixtures.

## Evidence

The specification defines OrderItem fields and relationships but leaves quantity, snapshot and transaction behavior pending.
